# Obelisk For Codex Benchmark

本文档定义 Obelisk For Codex 的基准测试与自迭代约束。Benchmark 的目标不是把项目变成浏览器、wiki 或 RAG 系统，而是验证 agent 是否能基于本地 SQLite 结构化历史进行 bounded query，并给出可追溯证据。

## Charter

- 原始 Codex JSONL 索引进 SQLite 后形成的结构化关系是 canonical evidence。
- 经用户批准写入并通过 `remember()` 注册的 markdown memory 是持久结论层；它必须回指 source session/message，不能替代 raw session evidence。
- summary、报告和分析说明只是输出视图，不能成为下一次检索的主事实来源，除非被用户明确批准为 markdown memory。
- synthetic lane 使用 fake HOME，不能触碰真实 `~/.codex`。
- local lane 只保存 redacted metadata、稳定 hash、计数和 human-review 标记，不能保存原始私有 session 内容。
- 任何 candidate 只能保存 patch、报告和合并建议；未经丸子明确允许不能合并。

## Lanes

### Synthetic Fixture Benchmark

Synthetic lane 由 `evals/obelisk-codex/data/synthetic/items.jsonl` 驱动。Runner 会为每个 fixture 创建 fake user profile，并调用真实 `scripts/runtime.mjs`，从而触发真实 indexer 和 query API。

覆盖边界：

- `apply_patch` patch header 与正文路径 false positive。
- PowerShell write command 路径抽取。
- true positive / false positive failure。
- summary 入口回到结构化 nearby evidence。
- `raw()` 恢复被截断原文。
- `remember()` / `memories()` 持久 memory 注册、召回和英文 guardrail。
- `overview()` 项目/session/memory orientation。
- `search()` 的 FTS rank 与 cwd filter。
- `sql()` read-only guard。
- FTS 标点、Windows path、中文路径。
- spawned agents / workflow-like run。
- no evidence honesty。
- incremental indexing。
- sandbox safety。
- repeated files 聚合。

### Local Reality Benchmark

Local lane 使用真实 `~/.codex`，只跑 smoke query：

- session/message/tool/failure/summary/workflow 计数。
- 最近 session 的 hash 化 id、hash 化 project 与 message_count。
- failure/tool/repeated-file/workflow 只保存 hash 或计数，不保存文本。

local lane 不声明 hard ground truth。结果默认 `needs_human_review: true`。

## Commands

```powershell
node evals/obelisk-codex/runners/run-api-eval.mjs --lane all --stage baseline
```

只跑 synthetic：

```powershell
node evals/obelisk-codex/runners/run-api-eval.mjs --lane synthetic --stage baseline
```

只构建某个 fixture fake HOME：

```powershell
node evals/obelisk-codex/runners/run-fixture-build.mjs apply-patch-doc-false-positive
```

## Output Contract

每个 synthetic item 输出：

```json
{
  "answer": "plain-language answer",
  "evidence": [
    {
      "type": "session|message|tool_call|tool_result|summary|workflow|subagent|file|raw",
      "id": "stable identifier",
      "session_id": "optional",
      "message_uuid": "optional",
      "tool_call_id": "optional",
      "file_path": "optional",
      "timestamp": "optional",
      "snippet": "short supporting text"
    }
  ],
  "used_apis": ["search", "context"],
  "query_notes": "bounded retrieval strategy",
  "uncertainty": [],
  "result_chars": 0
}
```

## Report Contract

Reports are Prism-authored artifacts. Each report directory contains:

- `prism-report.md` or the requested report file as the Prism template source.
- `template.html` when generated by the runner.
- `index.html` as the built, self-contained Prism HTML.
- `raw-results.json`
- `summary.json`
- `failures.json`

Every candidate report must end with:

```text
MERGE STATUS: NOT MERGED — WAITING FOR MARUKO APPROVAL
```
